# VAD Segments API Contract

## Overview
Defines the HTTP POST interface for submitting chunked audio segments generated by client‑side VAD to the server for processing. The server reassembles the chunks, optionally runs server‑side VAD fallback, performs STT, and returns a transcription response.

## Endpoint
- **URL:** `/api/vad/segments`
- **Method:** POST
- **Content‑Type:** `application/json`

## Request Payload
```json
{
  "request_id": "<uuid>",
  "client_vad": true,               // true if client VAD was used; false triggers fallback
  "chunks": [
    {
      "sequence": 1,
      "timestamp": 1713270000000,
      "data": "<base64 PCM>",
      "audio_format": {
        "sample_rate": 16000,
        "channels": 1,
        "encoding": "pcm_s16le"
      }
    },
    {
      "sequence": 2,
      "timestamp": 1713270000500,
      "data": "<base64 PCM>"
    }
    // … more chunks …
  ]
}
```

### Field Descriptions
- **request_id** *(UUID, required)*: Unique identifier for correlating logs and metrics.
- **client_vad** *(boolean, required)*: Indicates whether the client performed VAD. `false` forces server‑side VAD fallback.
- **chunks** *(array, required)*: Ordered list of audio chunks.
  - **sequence** *(int, required)*: Position of the chunk in the utterance.
  - **timestamp** *(int, required)*: Epoch ms when the chunk was captured.
  - **data** *(string, required)*: Base64‑encoded PCM audio.
  - **audio_format** *(object, optional)*: `sample_rate`, `channels`, `encoding`. If omitted, server assumes default PCM 16‑bit 16 kHz mono.

## Response Payload (Success)
```json
{
  "request_id": "<uuid>",
  "success": true,
  "transcription": "<text>",
  "confidence": 0.94,
  "processing_time_ms": 312,
  "vad_mode": "client",
  "error": null
}
```

### Response Fields
- **request_id**: Echoed from request.
- **success**: Always `true` for successful processing.
- **transcription**: Full text result from STT.
- **confidence**: Overall confidence (0‑1).
- **processing_time_ms**: End‑to‑end latency.
- **vad_mode**: `client` or `server` indicating which VAD performed detection.
- **error**: `null` on success.

## Response Payload (Error)
```json
{
  "request_id": "<uuid>",
  "success": false,
  "error": {
    "error_code": 400,
    "message": "Corrupted audio chunk",
    "details": "Chunk 3 failed validation"
  }
}
```

### Error Fields
- **error_code** *(int)*: HTTP‑like status (e.g., 400 for bad request, 415 for unsupported media).
- **message** *(string)*: Human‑readable description.
- **details** *(string, optional)*: Additional information for debugging.

## Validation Rules
- `request_id` must be a valid UUID.
- All `sequence` numbers must be positive and strictly increasing.
- `data` must decode to PCM matching the declared or default format.
- Total payload size must not exceed 10 MB.
- If `client_vad` is omitted, server assumes `false` (fallback).

## Non‑Functional Requirements
- Must respond within the NFR latency bound (≤ 500 ms).
- Must emit Prometheus metrics for VAD mode usage and processing time.
- Must log each request with anonymized request_id for GDPR compliance.
